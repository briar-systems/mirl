# Block layout and emission

`mirl.machine.layout` orders the blocks of an allocated and framed function and settles its branches. `mirl.machine.emit` hands the laid out functions of a module to masc, which encodes them into mink's object. This is the last stage of a register machine. mirl never encodes a byte and never writes an object file.

```
prepare(?build, a, ?target, isas)                  # err[compile.Error]
compile(a, ?module, ?build, ?target, options)      # res[object.Object, compile.Error]
lay(a, ?function)                                  # res[Laid, lay.Error]
emit(a, ?module, ?build, ?target, units)           # res[object.Object, emit.Error]
```

`mirl.machine.compile` is the register family's back end, which `mirl.target.compile` reaches through the family, and `compile` returns the object in memory. `emit` is the hand-over it ends in. The machine form text and masc's listing of the result are for debugging.

## Compilation

- `prepare` opens what depends on the target alone, once per build, into the build's state, which the register family holds from its `open` to its `close`, when `unprepare` gives it back: the record of the instruction set its basis holds (`mirl.machine.isa.of`), in the registry the family hands it, `mirl.target.register.isa.ISAS` for the register family, the locations of the machine's registers and memories, the selection table checked against the schema and indexed by opcode (`engine.index`), the set's moves and the frame code. A build opened for another target than the one given is refused there (`Error.foreign`), and so is a table with a defect (`Error.table`), before any module is compiled. masc found the set once when the machine was opened, so compilation names no set, imports no registry and looks nothing up by architecture again. The machine form text it writes reads the same registry.
- `compile` takes a module the pass schedule has run on, the build, the target, the allocator and the compilation's one `mirl.target.options.Options`. It opens a session of the module over the build's state: a selector lent the build's index (`engine.init`), which holds the inline assembly the module's selections parse, and the per function tables of extensions and rows. It reads the build and writes nothing through it.
- Every function with a body is selected with the clobbers each call's own row states (doc/machine/storage.md), allocated over the locations `allowed.of_build` lists, framed, its copies lowered to the set's moves (doc/machine/copy.md), its configuration state established where its vector instructions need one, its loops expanded (doc/machine/loop.md) and laid out. The functions are then emitted into one object.
- A function is made under the convention row its signature names, so one module mixes rows, as sysv64 and win64 functions on x86-64. The build resolves every row the target states once, and the session looks up each function's row once (`Scope.convention`). The function's row places its entry and returns and its inline assembly's frame pointer, and decides the registers its copies and configuration may write freely, the registers its frame saves, its frame's shape and the constraints its unwind records put on it, and the probe routine its prologue calls, which the convention lowering declares for every row a defined function is under and which is compiled, after the module's other functions, only when one of their frames calls it. A call's row is the one its callee's signature names, and decides the clobbers at that call site. A function whose signature names a row its target does not state is refused as `Error.convention`. The object's own traits stay the target's default row's.
- The steps are stated once, as the rows of `STAGES`, each a name and a run that reads the form the steps before it left (selected, allocated, framed, laid out) and gives the next. `through` runs one function through a sequence of steps, verifies it after each when the compilation is checked and hands it to a `Watch` when one is given. `compile` runs `STAGES` with no watch. The machine corpus walk (`src/machine/corpus.mach`) runs the same `STAGES` through `through`, its clobber and piece checks attached to the steps they name, so a step added to `STAGES` runs there with no edit to the walk.
- `compile` refuses with a `Failed`: the one `Error` of the compilation and, beside it, the function it refused, the step and the source location, the function none for a refusal of the module as a whole. A step given a form the steps before it did not leave is `Error.misplaced`, and a sequence that ends before layout is `Error.unfinished`. A refusal before any function, or by emission, is its own case.

## The entry and `mirl compile`

- `mirl.target.compile` is the entry mach calls, in three parts around a `Prepared` the caller makes once per target per build, holds in place across every module it compiles for that target and gives back after the last. `open(?prepared, a, ?target, added)` takes the one family of `mirl.target.families` that admits the target's declarations, lists the owners of the registry's opcode rows and has the family open the build with the extensions `added` names, which for the register family checks the selection table once (`prepare` above). A target no family admits is refused before anything runs (`Error.unserved`), and so is one several admit (`Error.several`). `open_in` does the same over a registry of families given. `compile(?prepared, a, ?module, options)`, whose `options` is the one `mirl.target.options.Options` every layer of the compilation reads, runs the neutral prefix and the family's rows over the build at `options.level` and hands the module to the family's back end. It returns a `Compiled`, the object and the warnings the compilation gave, each a case of `mirl.target.warning.Warning` the back end appended to the list it was handed, and `release(?compiled)` gives both back. The library writes no warning as text, so a front end words them. The register family (allocated registers, free control, physical addressing, register evaluation) compiles through `mirl.machine.compile`. `optimise(?prepared, ?module, options)` runs the schedule alone, as `compile` does before the back end, and `write(?prepared, a, ?object, output, ?writer)` lays the object out in the target's system's format. Every refusal of the entry, from opening the build to writing the object, is a case of the one `mirl.target.family.Error`. `close(?prepared)` gives the build back. `compile` and `write` read a `Prepared` and write nothing through it.
- `options.checked` turns on every opt-in check together, and is off by default: it verifies the module before the first pass and after every pass, verifies every function of the machine form after every stage (selection, allocation, the frame, the lowering of copies, the configuration state, the expansion of loops and layout), and has the allocation checker prove every allocation. With it off, a module handed over in memory is verified by none of them, so a caller that reads a module from text verifies it once before compiling it, as `mirl compile` does against the target they compile for. The refusals, the constant-time checks and the text reader's own validation run whatever it says. The machine form verifier (`mirl.machine.verify`) holds that every instruction a block places is one of the function's own, placed once, and stands against its opcode's row.
- `options.machine` and `options.listing` name writers for the machine form text of the laid out functions and masc's listing of the object, in the set's default syntax. Both are written only once the object is made, so a refused compilation writes nothing.
- A symbol at a marker position of a row (masc's `Shape.marker`) is a relocation that only marks the instruction for the linker, holding no bits, as RISC-V's `%tprel_add` on the `add` of a local exec access or `%tlsdesc_call` on a descriptor's `jalr`. The machine form carries it as an ordinary symbol operand with its mink kind, stood against the position like any other, and the hand-over gives it to masc with the marker's own fixup kind. A set states the rows that carry markers, so AArch64's TLSDESC call marker and x86's TLS hints are the same operand once masc states their rows.
- `options.relax` says whether the linker may relax the code. It is the build's one statement of relaxation and nothing else implies it: the target, its system and its convention never do. Its default is `mirl.target.options.RELAX`, one value stated once, on by the owner's ruling of 2026-10-23 (#286). The register family hands it to the relax mode of the set's record (`Isa.relax`, a `Relaxing` of the mode's on and off settings, nil for a set whose linker relaxes nothing), which `emit` sets on masc's builder before the first instruction. Under RISC-V's `relax` masc marks each relocation the linker may relax with `R_RISCV_RELAX`, and under `norelax` it marks none and the object is the one an unrelaxed build writes. mink keeps every marked instruction as written until its relaxation pass (mink#84), which is valid output. No code is aligned past the instruction granularity inside a section, so the object needs no `R_RISCV_ALIGN`.
- `options.apart` is the build's per-symbol section request (`mirl.target.options.Apart`, `code` and `data`), `SHARED` when the build states none. Under `code` each function a unit emits that states no section is placed in a nameless text section of its own, opened apart, and its jump tables share one nameless section of their own, so the linker can collect a function with its tables. Under `data` each global the module defines that states no section is placed in a nameless section of its own of the kind its facts pick. Without it every kind keeps one section per object, and the constants holding addresses share one relocated read-only section. A symbol that states a section keeps it whatever the request says, one section per name. How a format names a section of a kind is mink's.
- `mirl.target.compile.write(?prepared, a, ?object, w)` lays the object out in the default object format the target's system states, the first mink's row lists, through the build's registry of mink's formats, and refuses a system that states none.
- `mirl compile <file> [-o <path>] [--emit ir|machine|asm|obj]` is a thin wrapper over them, making one `Prepared` for its one module. A kind is a row of the command's own table, a stopping point as mach's `--emit` names it, and one run writes one kind, `obj` when `--emit` is not given, to the file `-o` names or to stdout. `ir` stops after the pass schedule (`compile.optimise`) and prints the module. The output is held until the compilation is done, so a refused one writes nothing. The target is the module's target statement, or the one `-t <sys>-<arch>` names with `--env`, `--abi`, `--isa`, `--ext` and `--code-model`, which mink's catalog parses and resolves (`mink.catalog.target.parse` and `resolve`) and masc's instruction set checks (`masc.isa.check`), and `-t` replaces the statement whole. A narrowing flag without `-t` is refused, since the statement states every part. `--kind` or `-k` names the product as mink's `--kind` does, `shared` taking the shared-object address model, `--level` (0 by default) sets `options.level`, `--verify` turns on `options.checked`, each `--float-relax` naming one float relaxation `options.floats` holds (see [doc/ir/target.md](../ir/target.md), Float relaxations), `--image` asks for the final image the target loads as it is rather than a relocatable object, which mink's link makes of the webassembly family's object and which no other family writes, and is its own axis since `-k` names the product a link makes of the code, an image or not, `--relax` and `--no-relax` set `options.relax`, its default when neither is given, each `--apart` names `functions` or `data` for `options.apart`, and each `--ext` names one extension the build adds to the target's isa through the family's `open`.
- The example programs in `test/example/` (arithmetic, a loop, a call, a global and a recursive function) each carry a start stub that calls `main` and hands its result to `__mirl_exit`. The example lane targets are one table, `test/lanes.sh`, one target per line: its spelling as `-t` takes it, its architecture's, its system's and its environment's rows in mink's catalog, its baseline as masc's selection and its convention's name. Covering a target is adding its line to the table.

## The example lane

`test/example.sh <run>` runs the example programs. It runs locally and is never part of CI, which builds mirl only. It writes into a fresh `out/example/<run>` and exits with the number of checks that failed.

- It needs mirl built (`mach build . -a cli`), the qemu user emulator of every lane target, `qemu-<arch>` for its architecture (`qemu-riscv64`, `qemu-riscv32`, `qemu-x86_64`, `qemu-aarch64`) and `git`. The masc and mink programs are built from the pinned `dep/masc` and `dep/mink`, each as a shadow project whose dependencies are mirl's own pins, once per set of pins into `out/example/tools/`, with the compiler `$MACH` (`mach` by default). `$MASC` and `$MINK` name built ones instead.
- The input set is every `test/example/*.mirl`. Its first line is its target statement, and it states the status its program exits with in a comment `# exits <n>: ...`. `test/example/exit.s` is `__mirl_exit`, which makes the Linux exit system call with no C library, and masc assembles it for each lane target.
- The lane targets are the lines of `test/lanes.sh`, the riscv64, riscv32, x86_64 and aarch64 linux gnu targets, each named as `-t` spells it (`linux-riscv64`), and the scripts keep no other copy. masc reads each as `-t` with its environment, selection and convention, `mink link` links it static for the same target under its environment and convention, and `qemu-<arch>` runs it. An example is built for each from a copy whose target statement spells that target's tuple and is its only change, so an example states nothing a lane target lays out otherwise. The start stub and `exit.s` are the same at either XLEN, since Linux sets the stack pointer before `_start` and under ILP32 `a0` holds the low word of the `i64` status, which is all the kernel reads. x86-64 links `exit-x86_64.s`, the exit system call through `syscall`, and windows has `exit-x86_64-windows.s`, kernel32's `ExitProcess`, for a link with mink. AArch64 links `exit-aarch64.s`, the Linux exit system call through `svc`, and darwin has `exit-aarch64-darwin.s`, its exit system call in x16 through `svc 0x80`, for a link with mink. The AArch64 lane's baseline is `armv8-a+fp+simd`, since aapcs64 passes floats and vectors in the FP and SIMD registers, which masc's `armv8-a` alone does not make mandatory. Linux enters `_start` with the stack pointer on 16 bytes, where a call would leave it 8 below, so the frames below the stub sit 8 bytes off the alignment SysV states, which the x86 frame code does not rely on, its xmm saves and reloads being unaligned moves.
- Round trip: `mirl compile --emit asm` writes the builder's listing, which masc assembles under the target's selection and traits. The listing is printed from what mirl asked the builder for, so reassembling it checks the builder's encoding independently. The lane shows `masc disassemble` of both objects, diffed, when their bytes differ, and that is only for reading: an object keeps an anonymous label as a nameless symbol, and masc's listing spells it by its syntax's anonymous stem (`.LtmpN` for RISC-V), which reassembly reads as a named local label, so the bytes of the files can differ in that name alone at every lane target.
- Run: `mirl compile` writes each example's object, `mink link` links it with the exit object into a static linux executable under the GNU environment, and the executable exits with the stated status under the lane target's qemu.

## Layout

- A block that only jumps is bypassed: everything that names it names the block its chain of such jumps ends at. The entry stays, so does a jump to itself, a chain that closes on itself and a jump a partner operand labels.
- Blocks are placed in a greedy topological order over the forward edges. A block is followed by its likely successor when that one is ready, the one deepest in loops and then the last listed, and otherwise by the ready block earliest in reverse postorder. Blocks the entry does not reach follow, and blocks that end in a fault go last. A fault is a row whose control is masc's `effect.FAULT`, unconditionally, as the `ud2` an `unreachable` selects to, which control never comes back from. A trap that comes back, as a system call, falls through.
- A jump to the block that follows is dropped. A conditional branch whose taken arm follows is inverted, so it jumps to the other arm, and the jump after it is dropped.
- The inverse of a branch is the first step of its row's relaxation in masc: the longer form of an out of range branch is its inverse over a jump. Its operands follow from the branch's by that step's sources. A branch whose row has no such form is left as it is.
- The function keeps its instruction ids, so what names an instruction, the frame's call frame facts and the labels, still does. `Laid.order` lists the blocks that stay. The function changes only when layout succeeds.

## Emission

- One builder holds the object's sections. A function is a named label exposed as a function symbol of the binding and visibility its linkage states, placed in the section it states, or else the text section, at the larger of the target's function alignment and the alignment it states. A function naming a section a global or another function names with another kind is refused (`Error.section`). A block is an anonymous label.
- The builder is given the object's name, `options.name`, which the front end states is no other object's in a link (`masc.build.name_object`): mach gives a module's path, `<module path>#tests` for its test object and the unit's name for an instance unit, and `mirl compile` the path of the file it reads. COFF has no weak definition, so masc moves each weak one to an external default symbol, `.weak.<name>.default.<object>`, which the PE format requires be external ("Auxiliary Format 3: Weak Externals"). Named after the object, two objects that each define the same replaceable symbol never define one name twice, whether or not either holds a global definition. A merged function is not weak: its code and its jump tables are placed by `masc.build.section.copy` in sections of their own in the group its copy signature signs, or on Mach-O in atoms of the coalesced sections the dialect names, so the link keeps one copy of the function and its tables together. On Mach-O a replaceable definition is placed in those coalesced sections too (`masc.build.section.replaceable`), as the format supports a weak definition only in a coalesced section.
- A function symbol's size is its range: its own label and an anonymous label placed after its last instruction, before the alignment padding of whatever follows. masc measures the distance between them once it has laid the section out, so relaxation is counted and padding is not, and mirl never counts a byte. Each unit's end label is made before any function is named, so a symbol is exposed once with its range whether a call or its unit names it first. A function no unit emits states no size. A part of a function placed apart, as a cold part, would be a unit of its own symbol and range. The size is a fact of mink's neutral symbol, and how a container carries it is mink's: ELF states it as `st_size`, COFF in its function table, and Mach-O by the next symbol.
- Every global the module defines is a named label exposed as a data symbol, or a thread-local one, of its linkage and its type's size, after the functions. It is placed in the section it states, or the one its facts pick (doc/ir.md), at its alignment or its type's. A section is opened once per name, and a global naming a section the code or another global names with another kind is refused. The globals that state no section share one section of each kind. A nameless section, which the target places, is aligned to `code.text` when its kind executes and to `code.data` otherwise. A named section is the module's placement and takes the alignment of what is placed in it, each function at its entry's and each global at its own, so a global placed at an offset in a section of its own, as a boot sector's signature at 510, keeps its type's alignment. The object states the target's operating system and environment from the target's rows (`mirl.target.record.state`), and none for freestanding, so a conversion that reads them, as Mach-O's thread-local descriptors bind an accessor only Darwin's loader provides, finds them.
- An initial value is its bytes, laid out by the data layout in the architecture's byte order, and a datum for each address in it, an absolute reference of the pointer's width to the symbol plus its offset, which masc relocates as a fixup. One every bit zero is zero fill, which holds no bytes in a zero filled section. A global the module does not define is an undefined symbol, named when an operand or a datum first names it.
- An operand takes the masc value its row's position reads: a register, an immediate, an enumerant or a condition, or a label with a fixup. A block operand is a label of the operand's own fixup. A symbol operand names the function's or global's label and takes the fixup kind the set binds its relocation kind to, read through an index of the set's bindings built once. Where several fixup kinds are bound to one relocation kind, the operand's own is taken, else the emission is refused.
- An instruction another names as a partner (`label n`, `partner n : kind`) is an anonymous label of its own, placed before it, so a pc-relative low part's relocation names its high part. The labels map one to one.
- A jump table (the pseudo `table`) emits nothing in the code. After its function's end label it is laid out in the one nameless section, or under `options.apart.code` the function's own nameless section, of the kind a constant holding addresses is placed in under the target's relocation model (read-only data under static and near, read-only after relocation under pie and image), aligned to the pointer's width: its label, which the jump's address names as a partner, then one absolute datum of the pointer's width per block it names, the block's label, which masc relocates. A range or call frame fact at it is stated where it stands, after the jump. A table on a target that states no address model or no pointer is refused (`handover.Error.table`).
- An inline assembly block is handed to masc whole, each operand at the location allocation gave it, and masc encodes it at the cursor. A symbol its text names, as `call main`, is the builder's label of that name. Once every unit and global is emitted, each such label nothing placed or exposed is made a symbol of the object: the module's function or global of that name, with its own linkage and kind, when the module has one, else an undefined symbol of global binding and default visibility, as an IR declaration is, with no kind, since the text does not state what it names.
- A fixup whose relocation covers the instructions after it, as RISC-V's call pair, is written with them as one sequence, as the set's spans state. masc attaches the marker a span states only under the modes its `when` holds. mirl sets no mode, so under RISC-V's initial `norelax` no relocation carries `R_RISCV_RELAX`.
- Alignment and fill come from the target's code declaration: `code.function` aligns each function, `code.text` aligns the section, and `code.fill` is the byte code is padded with. masc takes one byte, so a fill that is not one byte repeated is refused.
- The traits of the object that the convention owns come from the convention row (`Convention.traits`). Each RISC-V row states the float ABI, `riscv-float-abi` as `soft`, `single` or `double`. The builder passes them to the object unchanged, and masc refuses a set whose required axis is not stated.
- `instruction.fixed` is masc's `emit.fixed`: it states the same fact, a row's fixed register for an operand, so mirl keeps no reading of the effect.

## Frame, line and debug facts

- A function whose architecture masc states a starting frame for is a frame of the builder: `cfi_start` at its label and `cfi_end` after its last instruction. Each call frame fact of `Framed.facts` is handed to masc through `cfi` in order at its instruction, before it or after it as the fact states. A fact at an instruction layout left in no block is refused (`handover.Error.fact`). mink lowers the frame records to the format's call frame information.
- A module whose debug table states a source file hands masc its files in table order, so a file's index is its id's, and states each change of source location along the laid out code through masc's `line.location`, before the instruction it begins at. An instruction with no location is line 0 with no statement flag, never a neighbour's line. mink lowers the line records to `.debug_line`.
- Once the builder finishes, `mirl.debug.records` states the debug records on the object: the unit, the types, the globals by their symbols, the functions and variable ranges by marks at their labels' places, and the inlined runs. mink lowers them to `.debug_info`, `.debug_abbrev`, `.debug_addr`, `.debug_loclists` and `.debug_rnglists`, named as the object format names them, its strings in place, and writes the unit's `DW_AT_stmt_list` against its own line table.
- Where each variable is comes from `mirl.machine.range`, computed over the framed function from its value binding records (doc/ir/debug.md). A range begins and ends at labels placed before the instructions it begins and ends at, or at its block's end when it runs to it. The runs of code inlined at each site are delimited by labels where the site of the instructions changes.

## Refusals

An instruction is refused, naming the function, the instruction and the operand, when it is a pseudo no stage expanded, still names a virtual register or a frame slot, names a location of a memory-backed class, sits at an `id` operand position, which a family that keeps no SSA ids does not give, names a relocation kind the set binds no fixup kind to, or has a label problem or a span the block cannot hold.

A global is refused, naming it, when its initial value holds an address and the target states no address model, it names a section another names with another kind, the data layout gives its type no extent, or an address in its initial value is wider than a datum masc relocates.

The object is refused as `Error.unmapped` when masc finishes it with a relocation whose kind the object's format does not map for the architecture (masc's `build.NO_RELOCATION`). It names the function or global the relocation aims at, none for a block or a marker, and keeps masc's refusal, whose mink failure names the kind and the format. `mirl compile` reports it as refused input. Any other refusal of masc's is `Error.builder`.

## Limits

- PE and Mach-O images are gated by mink#70 and mink#73. Objects carry their frame records on every format: mink lowers them to `.eh_frame` in ELF, `.pdata` and `.xdata` in COFF, and `__compact_unwind` with `__eh_frame` where needed in Mach-O.
- `DW_AT_stmt_list` is offset 0 with no relocation, which holds for one unit per object.
- The unit states `DW_LANG_C11`, since the IR names no source language.
- A slot whose offset scales, salvage steps over a slot, and a slot of a realigned frame or the outgoing area are not stated, so the variable is optimised out there.
- The variables of an inlined body are scoped at the subprogram, not the inlined subroutine.
- A record standing at an instruction a stage dropped moves to the instruction that follows.
- Default section names mirror a mink fact, deleted by #222 (blocked by mink#214).
- The listing is refused, as `Error.listing`, for an object masc cannot state as source. The error carries masc's refusal, whose message names the construct the listing has no form of, and the function or global it is about: the one its label names, or the one placed last at or before where it was found. `mirl compile` reports all of it. COFF listings refuse frames, which no call frame directive the listing writes states, until the .seh half of masc#484. Mach-O listings refuse labels held as no symbol, whose names the assembler would make symbols, until masc#518. The round trip therefore covers the ELF targets only.
- x86_64 listings of rel32 branches to block labels and of rip-relative symbols are refused until masc#457.
- The start stubs cannot make the exit syscall, since the IR has no inline assembly (#44). They call `__mirl_exit`, which the example lane links from `test/example/exit.s`, or `exit-<arch>.s` for an architecture that has one, assembled by masc.
- `mirl compile` writes to standard output unless `-o` names a file, the object's bytes included.
